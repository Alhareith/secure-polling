# مواصفة المتطلبات البرمجية

## منصة «صَوِّت» للاستطلاعات السرية القابلة للتدقيق

| الحقل | القيمة |
|---|---|
| المعرّف | SRS-SV-001 |
| الإصدار | 0.1 — مسودة مراجعة |
| الحالة | متطلبات قبل التنفيذ؛ ليست تصريحًا ببدء البرمجة |
| تاريخ الإصدار | 23 أغسطس 2026 |
| اللغة الأساسية | العربية |
| المجال | استطلاعات داخلية مغلقة لمجموعات صغيرة إلى متوسطة |

## 1. الغرض من الوثيقة

تحدد هذه الوثيقة، بصورة قابلة للتنفيذ والاختبار، ما يجب أن تبنيه منصة «صَوِّت»، وما يجب أن تمنعه، وحدود الأمان التي يجوز ادعاؤها. وهي المرجع قبل كتابة أي كود، ولا يجوز تغيير متطلب مرقّم أو إضافة وظيفة تؤثر في الخصوصية أو العد أو دورة الاستطلاع دون تحديث هذه الوثيقة أولًا.

> **قاعدة تفسير:** الكلمات **يجب** و**لا يجوز** و**لن** تمثل التزامًا إلزاميًا. كلمة **يمكن** تمثل خيارًا غير إلزامي. وكل متطلب ذي معرّف فريد يجب أن يملك اختبار قبول أو مراجعة معمارية موثقة.

## 2. تعريف المنتج وحدوده

### 2.1 تعريف المنتج

«صَوِّت» تطبيق ويب لخدمة الاستطلاعات السرية داخل مجموعة مغلقة. ينشئ مشرف مصادق عليه استطلاعًا، ويولّد رموزًا فردية لمرة واحدة، ويوزعها خارج المنصة. يدخل المصوّت من رابط الاستطلاع ورمزه فقط، ثم يرسل بطاقة تصويت مشفّرة. بعد الإغلاق، يحسب النظام النتيجة ويصدر تقرير تدقيق موقّعًا.

### 2.2 الهدف التشغيلي

الهدف هو تقليل ضغط التصويت العلني، ومنع إعادة الاستخدام الاعتيادي للرموز، وفصل أهلية التصويت عن اختيار المصوّت في التخزين والواجهة، مع كشف التعديل على التقرير والسجل. لا يهدف المنتج إلى الانتخابات الرسمية أو إلى إخفاء هوية تشفيري كامل ضد مشغّل الخادم.

### 2.3 حدود النطاق

| داخل النطاق في الإصدار الأول | خارج النطاق صراحة |
|---|---|
| استطلاع مغلق حتى 200 رمز مؤهل | انتخابات سياسية أو حكومية أو ملزمة قانونيًا |
| اختيار واحد، اختيار متعدد، نعم/لا | تصويت ترتيبي أو أوزان أو تفويض أصوات |
| حساب مشرف فقط | حسابات، أسماء، أو عناوين بريد للمصوّتين |
| رموز عشوائية أحادية الاستخدام | توزيع SMS أو بريد إلكتروني أو تكامل هوية خارجي |
| نتائج بعد الإغلاق فقط | نتائج حية أو عد جزئي أثناء التصويت |
| SQLite في عملية واحدة محلية | عدة مثيلات تطبيق أو تشغيل بلا قرص دائم |
| مختبر خوارزميات أكاديمي منفصل | استعمال خوارزمية كلاسيكية أو DES3 في حماية التصويت |
| تقرير نهائي موقّع وسجل تدقيق | Blockchain أو بروتوكول انتخابات مجهولية متقدمة |

## 3. المصطلحات والتعريفات

| المصطلح | التعريف الدقيق |
|---|---|
| المشرف | الشخص الوحيد الذي يملك حسابًا ويستطيع إدارة استطلاعاته ضمن صلاحياته |
| المصوّت | شخص يملك رمز تصويت صالحًا ولا يملك حسابًا في المنصة |
| الرمز | قيمة عشوائية صالحة لمرة واحدة تثبت أهلية التصويت، ولا تمثل هوية المصوّت |
| بصمة الرمز | ناتج HMAC-SHA256 للرمز مع `token_pepper`؛ هو ما يحفظ بدل الرمز الخام |
| بطاقة التصويت | تمثيل مشفّر لاختيار مصوّت واحد، ولا يحمل رمزًا أو هوية |
| الإيصال | قيمة عشوائية تثبت قبول بطاقة، ولا تكشف الاختيار ولا تصلح لإثباته لطرف ثالث |
| الاستطلاع المنشور | استطلاع موقّع ومقفّل الإعدادات قبل فتح التصويت |
| التقرير النهائي | ملخص النتائج وحالة التدقيق، موقّع رقمياً بعد العد |
| السجل | أحداث إدارية ونظامية تسلسلية، لا يضم أصوات الأفراد أو الرموز الخام |
| المختبر الأكاديمي | بيئة منفصلة لا تتصل ببيانات الاستطلاعات الحقيقية وتنفذ تجارب خوارزميات المقرر |

| AC-02 | الخادم يملك ساعة UTC صحيحة | جميع الأوقات تخزن UTC ويعتمد عليها فتح/إغلاق الاستطلاع |

## 6. نموذج العملية وقواعد الأعمال

### 6.1 حالات الاستطلاع

```text
DRAFT → PUBLISHED → OPEN → CLOSED → TALLIED → ARCHIVED
                    ↘ CANCELLED
PUBLISHED ───────────↗ CANCELLED
```

| الحالة | الوصف | عمليات مسموحة | عمليات ممنوعة |
|---|---|---|---|
| `DRAFT` | مسودة لم تنشر | تعديل كل الإعدادات أو حذفها | إصدار رموز أو استقبال بطاقات |
| `PUBLISHED` | إعدادات موقّعة ومقفّلة قبل بدء النافذة | عرض الرابط، وإصدار/إلغاء رمز غير مستخدم | تعديل محتوى أو قواعد الاستطلاع |
| `OPEN` | ضمن نافذة التصويت | قبول بطاقة صالحة فقط، متابعة عدد المشاركة | تعديل إعدادات أو عرض نتائج |
| `CLOSED` | انتهت النافذة أو أُغلق يدويًا | التدقيق والعد | قبول بطاقة أو تعديل إعدادات |
| `TALLIED` | تقرير نهائي موقّع صدر | عرض التقرير والتحقق | تغيير البطاقات أو النتيجة |
| `CANCELLED` | أُلغي قبل العد | عرض سبب الإلغاء والسجل | التصويت أو العد |
| `ARCHIVED` | انتهى الاحتفاظ التشغيلي | القراءة المحدودة للتقرير | أي تعديل |

### 6.2 قواعد الأعمال

| المعرّف | القاعدة |
|---|---|
| BR-01 | لكل استطلاع مالك مشرف واحد في الإصدار الأول. |
| BR-02 | لا يقبل الاستطلاع أقل من خيارين في نوعَي الاختيار الواحد والمتعدد. |
| BR-03 | نوع نعم/لا ينشئ خيارين ثابتين محليين ولا يسمح بإضافة خيار ثالث. |
| BR-04 | نص العنوان من 3 إلى 120 حرفًا، والسؤال من 3 إلى 500 حرف، ووصف الاستطلاع اختياري حتى 1,000 حرف. |
| BR-05 | اسم الخيار بعد إزالة المسافات من 1 إلى 120 حرفًا، ويجب أن يكون فريدًا داخل الاستطلاع بعد التطبيع النصي. |
| BR-06 | في الاختيار المتعدد، يكون `min_choices` أكبر من أو يساوي 1 و`max_choices` أكبر من أو يساوي `min_choices` وأصغر من أو يساوي عدد الخيارات. |
| BR-07 | بداية النافذة تساوي الوقت الحالي أو تقع بعده، ونهايتها تقع بعد البداية بخمس دقائق على الأقل ولا تزيد المدة على 30 يومًا. |
| BR-08 | يمكن للمشرف إغلاق استطلاع مفتوح يدويًا، ولا يمكنه فتحه من جديد بعد الإغلاق. |
| BR-09 | يمكن إصدار 1 إلى 200 رمز لكل دفعة، ولا يجوز إعادة عرض رمز خام محفوظ من دفعة سابقة. |
| BR-10 | الرمز الملغى لا يقبل، ولا يستبدل إلا إذا كانت حالته `UNUSED`. |
| BR-11 | الرمز المستخدم لا يعاد تفعيله ولا يستبدل من دون إنشاء استطلاع جديد. |
| BR-12 | بطاقة واحدة فقط تقبل لكل رمز، ولا يسمح بتعديل البطاقة أو إلغائها في الإصدار الأول. |
| BR-13 | لا تعرض النتائج أو مؤشرات تقدم الخيارات أو العد الجزئي قبل حالة `TALLIED`. |
| BR-14 | لا يتضمن التقرير النهائي اختيارات فردية أو رموزًا أو بيانات تعريفية. |
| BR-15 | أي عملية حساسة تكتب حدث تدقيق لا يتضمن بيانات سرية أو بطاقة قابلة لفك التشفير. |
| BR-16 | المختبر الأكاديمي لا يصل إلى الجداول التشغيلية ولا إلى مفاتيحها ولا إلى أي بطاقة حقيقية. |

## 8. المتطلبات الوظيفية التفصيلية

### 8.1 المصادقة وإدارة جلسة المشرف

| المعرّف | المتطلب | المدخلات | المخرجات والنتيجة | حالات الفشل ومعيار القبول |
|---|---|---|---|---|
| FR-AUTH-01 | يجب ألا توفر المنصة تسجيلًا عامًا. ينشأ المشرف الأول عبر آلية تهيئة محلية موثقة فقط. | اسم مستخدم وكلمة مرور تهيئة محلية | حساب مشرف | لا يظهر رابط «إنشاء حساب» في الواجهة العامة. |
| FR-AUTH-02 | يجب أن تقبل صفحة الدخول اسم مستخدم وكلمة مرور فقط. | username، password | جلسة مشرف أو رسالة عامة | الرسالة لا تكشف أي الحقلين خاطئ. |
| FR-AUTH-03 | يجب أن تمنع محاولة الدخول بعد 5 إخفاقات خلال 15 دقيقة لنفس الحساب أو المصدر لمدة 15 دقيقة. | محاولات دخول | حظر مؤقت | اختبار ست محاولات خاطئة ينتج حظرًا ولا يسجل كلمة المرور. |
| FR-AUTH-04 | يجب أن تنشئ المنصة جلسة خادم عشوائية بعد الدخول الناجح، لا بيانات هوية حساسة داخل cookie. | اعتماد صحيح | cookie جلسة | cookie تحمل `Secure` و`HttpOnly` و`SameSite=Lax` في HTTPS. |
| FR-AUTH-05 | يجب أن تنتهي جلسة المشرف بعد 30 دقيقة من عدم النشاط أو 8 ساعات كحد أقصى من الإنشاء. | وقت الخادم | إعادة مصادقة | لا ينجح طلب إداري بعد انتهاء الجلسة. |
| FR-AUTH-06 | يجب أن تنهي عملية الخروج الجلسة فورًا وتبطل معرفها على الخادم. | طلب خروج صالح | جلسة منتهية | إعادة استخدام cookie لا تفتح لوحة الإدارة. |
| FR-AUTH-07 | يجب أن تطلب إعادة إدخال كلمة المرور قبل النشر أو الإلغاء أو إغلاق استطلاع أو إصدار تقرير نهائي. | كلمة مرور حديثة | تصريح حساس قصير | يفشل الإجراء إذا لم تحدث إعادة المصادقة خلال 10 دقائق. |

### 8.2 إنشاء الاستطلاع وإدارته

| المعرّف | المتطلب | المدخلات | المخرجات والنتيجة | حالات الفشل ومعيار القبول |
|---|---|---|---|---|
| FR-POLL-01 | يجب أن ينشئ المشرف مسودة تتضمن العنوان والسؤال والنوع والخيارات والنافذة الزمنية. | حقول المسودة | `DRAFT` | ترفض كل قيمة تخالف BR-02 إلى BR-07. |
| FR-POLL-02 | يجب أن يدعم النوع `SINGLE` و`MULTI` و`YES_NO` فقط. | نوع | نموذج قواعد مناسب | يرفض نوعًا غير معرّف. |
| FR-POLL-03 | يجب أن ينشئ `YES_NO` الخيارين «نعم» و«لا» ولا يسمح بتحريرهما. | نوع نعم/لا | خياران ثابتان | لا تقبل الخدمة خيارًا ثالثًا أو حذف خيار ثابت. |
| FR-POLL-04 | يجب أن يتيح للمشرف حفظ المسودة وتعديلها قبل النشر فقط. | بيانات معدلة | مسودة محدّثة | يفشل التعديل بعد `PUBLISHED`. |
| FR-POLL-05 | يجب أن يحسب النظام تمثيلًا قانونيًا ثابتًا لإعدادات المسودة قبل النشر. | إعدادات صالحة | `configuration_hash` | يعطى التمثيل نفسه البصمة نفسها مهما كان ترتيب حقول النموذج غير المؤثر. |
| FR-POLL-06 | يجب أن يوقع النظام إعدادات الاستطلاع عند النشر ويغير الحالة إلى `PUBLISHED`. | إعادة مصادقة صالحة | توقيع ووقت نشر | يفشل النشر إذا غاب توقيع أو لم تكن المسودة صالحة. |
| FR-POLL-07 | يجب أن يقفل النظام السؤال والخيارات والنوع والقيود والنافذة وقاعدة النتائج بعد النشر. | طلب تعديل بعد النشر | رفض | لا يحدث تغير في الحقول المقفلة. |
| FR-POLL-08 | يجب أن يفتح النظام الاستطلاع فقط عندما يحل `starts_at`، وأن يرفض التصويت قبل ذلك. | وقت خادم | حالة فعالة أو رفض | لا تعتمد الحالة على وقت جهاز المتصفح. |
| FR-POLL-09 | يجب أن يغلق النظام تلقائيًا عند `ends_at` أول مرة يعالج طلبًا ذا صلة، أو يدويًا من المشرف مع إعادة مصادقة. | وقت أو طلب إغلاق | `CLOSED` | لا تقبل أي بطاقة بعد الإغلاق. |
| FR-POLL-10 | يجب أن يسجل النشر والإغلاق والإلغاء في سجل التدقيق. | الحدث | AuditEvent | الحدث لا يتضمن خيارًا أو رمزًا خامًا. |

### 8.3 الرموز وأهلية التصويت

| المعرّف | المتطلب | المدخلات | المخرجات والنتيجة | حالات الفشل ومعيار القبول |
|---|---|---|---|---|
| FR-TOKEN-01 | يجب أن يولد النظام رموزًا باستخدام مصدر عشوائية تشفيري. | عدد من 1 إلى 200 | رموز خام مؤقتة وبصمات مخزنة | لا تستخدم `random` أو عدادًا لتوليد الرمز. |
| FR-TOKEN-02 | يجب أن يظهر الرمز الخام في التوليد أو التصدير الآني مرة واحدة فقط. | دفعة رموز | قائمة قابلة للطباعة أو النسخ | بعد مغادرة الشاشة لا يسترجع الرمز من القاعدة. |

## 10. نموذج البيانات المنطقي والقيود

| الكيان | الحقول المنطقية الإلزامية | القيود |
|---|---|---|
| `administrators` | id، username، password_hash، role، created_at، last_login_at | username فريد؛ لا كلمة مرور خام |
| `admin_sessions` | id، administrator_id، expires_at، idle_expires_at، created_at | تنتهي وتبطل عند الخروج |
| `polls` | id، public_id، owner_id، title، question، description، vote_type، min_choices، max_choices، state، starts_at، ends_at، config_hash، config_signature، key_id | public_id فريد؛ state محكوم بآلة الحالات |
| `poll_options` | id، poll_id، label، display_order، immutable_after_publish | فريد داخل poll بعد التطبيع |
| `voter_tokens` | id، poll_id، token_hmac، status، issued_at، used_at، revoked_at | token_hmac فريد داخل poll؛ لا رابط إلى ballots |
| `ballots` | id، poll_id، ciphertext، nonce، tag، key_id، ciphertext_hash، receipt_hmac، submitted_at، status | لا token_id ولا هوية؛ nonce فريد لكل key_id |
| `audit_events` | id، poll_id، event_type، occurred_at، payload_digest، previous_hash، event_hash | لا أسرار أو بيانات اختيار فردية |
| `result_reports` | id، poll_id، totals_json، report_hash، signature، key_id، created_at | تقرير واحد فقط لكل poll في TALLIED |
| `crypto_key_metadata` | key_id، purpose، algorithm، created_at، retired_at | metadata فقط؛ لا مفتاح خاص |

### قيود قواعد البيانات الحرجة

1. يجب ألا يوجد عمود أو فهرس أو foreign key في `ballots` يمكنه الإشارة إلى `voter_tokens`.
2. يجب أن يكون انتقال `voter_tokens.status` من `UNUSED` إلى `USED` تحديثًا شرطيًا ذريًا.
3. يجب أن يكون `(poll_id, token_hmac)` فريدًا.
4. يجب أن يكون `(key_id, nonce)` فريدًا أو أن يولد nonce بطريقة تجعل التكرار عمليًا مستحيلاً مع اختبار حراسة.
5. يجب أن تكون timestamps UTC وغير قابلة لتعديل المستخدم.
6. يجب أن يكتب التغيير إلى البطاقة والرمز والتدقيق ضمن حدود المعاملة نفسها.

## 12. تسلسل التنفيذ الذي لا يجوز عكسه

| المرحلة | مخرجاتها | شرط الانتقال |
|---|---|---|
| P0 | اعتماد هذه المواصفة وملحق قرارات المراجعة | لا توجد نقاط مفتوحة حرجة |
| P1 | domain: entities، value objects، policies، state machine، اختبارات وحدة | انتقالات الحالات وقواعد الاختيار مغطاة بالاختبارات |
| P2 | schema وrepositories وSQLite WAL ومعاملات وmigrations | اختبار ذرية الرمز/البطاقة ينجح |
| P3 | مصادقة المشرف والجلسات وCSRF وheaders | اختبارات دخول وخروج وحظر وCSRF تمر |
| P4 | إنشاء الاستطلاع والنشر والقفل والرموز | لا يمكن تعديل ما نُشر |
| P5 | قبول بطاقة AES-GCM وHMAC وإيصال | اختبار تزامن لرمز واحد يثبت قبولًا واحدًا |
| P6 | الإغلاق والعد وسجل التدقيق والتقرير RSA-PSS | تقرير معدل يفشل تحققه |
| P7 | صفحات Jinja والاستجابة والإتاحة | اختبارات قبول ووصول أساسية تمر |
| P8 | المختبر الأكاديمي والخوارزميات بالتتابع | يثبت الاختبار انفصال المختبر عن بيانات التشغيل |

## 13. قرارات الإصدار الأول المعتمدة

| المعرّف | القرار الافتراضي المقترح | سبب الحاجة إلى الحسم |
|---|---|---|
| OD-01 | لا يسمح للمصوّت بتعديل اختياره بعد الإرسال | التعديل يضيف تعقيدًا في السجل والخصوصية والعد |
| OD-02 | تظهر النتائج بعد `TALLIED` فقط | يمنع تأثير النتائج الجزئية |
| OD-03 | المشرف يملك استطلاعاته فقط؛ لا مشرفون متعددون على استطلاع واحد في v1 | يقلل نموذج الصلاحيات والتدقيق |
| OD-04 | لا يدعم النظام استيراد قائمة أسماء للمصوّتين | يحمي مبدأ عدم جمع الهوية ويمنع خصوصية زائدة |
| OD-05 | احتفاظ تشغيلي بالتقرير وسجل التدقيق 90 يومًا قابلًا للضبط، ثم أرشفة أو حذف مضبوط | يلزم وضع سياسة بيانات واضحة |

> **حالة المراجعة:** اعتمد المستخدم القرارات OD-01 إلى OD-05 في 23 أغسطس 2026. لا تغير هذه القرارات إلا بتعديل إصدار المواصفة قبل التنفيذ.

## 14. معايير قبول المواصفة قبل بدء الكود

لا تبدأ مرحلة P1 إلا إذا تحققت الشروط الآتية:

1. اعتمد المستخدم OD-01 إلى OD-05 في 23 أغسطس 2026.
2. راجع المستخدم القيد الأمني الخاص بعدم وجود مجهولية مطلقة ضد الخادم نفسه.
3. وافق المستخدم على عدم استخدام الخوارزميات الكلاسيكية وDES3 في الحماية التشغيلية.
4. تأكد أن نشر SQLite، إن وقع، سيكون على مثيل واحد وقرص دائم؛ وإلا يُستبدل القرار بـ PostgreSQL قبل التنفيذ.
5. ثبتت أولوية تنفيذ P0 إلى P8، ومنع إضافة واجهة أو خوارزمية قبل طبقة المجال والاختبارات المناسبة.
